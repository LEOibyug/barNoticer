## 仍需修正

### R1 / P2：尺寸相同时跳过屏幕位置修正

位置：`barNoticer/AIAssistantPanelController.swift:108–119`、`:146–164`。

屏幕变化 observer 将 panel.frame.size 原样传入 resize；resize 在尺寸与 clamped 相等时提前返回，因此未执行 constrain。若可见区域位置改变但仍容得下当前尺寸，控制器不会自行把越界位置拉回。首次打开的居中越界已修复，但“屏幕变化后四边约束”尚未闭环。操作系统可能在部分场景自动调整，不能依靠这种行为替代明确约束。

修正要求：先计算完整目标 frame，再比较完整 frame 是否变化，而不是只比较尺寸。分别验证尺寸变化和仅位置变化两个场景。重开时 panel.screen 优先会继续选上次所在屏幕，也不能直接等同注释中的“当前交互屏幕”；屏幕选择规则需明确。

验收：输入相同窗口尺寸、变化后的可见区域原点或边界，最终四边距至少 12 pt；保留顶部锚定和首次居中行为。

### R2 / P2：提醒示例绕过减少动态效果策略

位置：`barNoticer/ReminderPresenter.swift:168–177`。

实际提醒和后台回复已检查 MotionPreferences.reduceMotion，但 previewChanged 仍无条件 showFlash，并保留固定等待。减少动态效果开启后，用户点击设置中的“提醒示例”仍会播放自定义边缘动画，和真实提醒不一致。

修正要求：预览与真实呈现使用同一动效决策；减少动态效果时跳过光效及预等待，直接展示示例面板。静态范围预览仍可显示，因为它不属于动态效果。

验收：同一系统偏好下，真实提醒、后台回复、提醒示例三个入口都没有遗漏；关闭偏好后仍保留单次轻提示。

### R3 / P2：外扩滑块的静态边界预览不可见

位置：`barNoticer/ReminderPresenter.swift:134–135`、`:151–157`、`:450–455`。

showBoundary 使用 animated=false 创建 ReminderFlashView；新 view 初始化 highlightLayer.opacity=0，只在 startFlashing 中通过 CAAnimation 改变可见度。静态路径不会调用 startFlashing，所以边界始终透明。

修正要求：静态模式显式设置可见模型层透明度，动画模式单独设置动画起点；不为静态预览强行播放动画。预览结束仍移除窗口。

验收：拖动“热区闪烁外扩”时边界持续可见，松开/离开设置后按既有规则清理；减少动态效果开启时也能观察静态范围。

### R4 / P2：外扩量被内部 inset 抵消

位置：`barNoticer/ReminderPresenter.swift:141`、`:463–467`。

外层窗口先在热区四边扩展 expansion，内层 highlightLayer 又在 bounds 四边内缩同样的 expansion。因此屏幕上的边框始终回到原热区尺寸，滑块改变的是透明窗口范围和部分圆角，不是用户可见的外扩范围。原有外扩设置虽然还在，但含义已失效。

修正要求：边框对应真正外扩后的目标范围，只为描边留必要内边距；若产品决定取消外扩能力，应另行明确更改设置，而不是保留无效果的控件。本轮建议保留原设置。

验收：以相同热区比较 0、20、80 pt 三个值，外框尺寸逐级增加，预览与实际提示范围一致；不恢复多圈黄色扩散动画。

## 视觉设计补充意见（非阻塞缺陷）

1. 岛展开和宽窄切换仍保留 0.62 秒，比专项 spec 的建议节奏慢。它不是正确性错误，建议通过实际录屏比较后再决定，避免为“统一数字”牺牲流畅度。
2. 新建面板添加按钮仍位于时间计划行，备注/错误在其下方；可进一步把主操作组织为稳定尾部区域。小屏滚动时至少保证操作容易找到，当前 scrollIndicators(.never) 会减弱溢出提示。
3. 使用系统材质和阴影已朝原生方向靠近；无需为达标而强行引入更多玻璃特效。下一轮重点是同版运行包的浅/深色、长内容、窗口切换和完整动效证据。
4. 没有专门检查降低透明度并不自动等于失败：系统 material 可能已处理部分情况。应验收实际结果，再决定是否添加应用级分支。
