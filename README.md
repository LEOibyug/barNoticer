# barNoticer

barNoticer 是一个轻量的 macOS 待办工具。它利用 MacBook 屏幕顶部摄像头刘海附近的空白区域，把待办事项、快速输入和 AI 辅助整理做成一个类似“灵动岛”的常驻入口。

这个项目主要面向带刘海的 Apple Silicon Mac。应用默认不常驻 Dock，当鼠标移动到顶部热区时，岛会从刘海位置自然展开；需要更完整的管理能力时，可以打开主面板进行编辑和设置。

## 功能特性

- 从屏幕顶部刘海区域展开的待办岛面板。
- 支持窄体和宽体两种岛模式。
- 支持按重要性分组，也支持按自定义分组展示，自定义分组可拖动调整顺序。
- 岛内可快速查看、展开备注、完成事项，并可一键唤出新建事项小面板。
- 新建事项使用独立轻量小面板，支持全局快捷键唤出。
- 事项支持标题、备注、重要性、完成状态、自定义分组、可选截止时间和多时间点安排。
- 支持一次性多时间点事项，也支持每天、每周、每月和每 N 天重复事项。
- 带时间安排的事项会显示最近一次未到来时间点的剩余时间。
- 可在设置中手动调整唤起热区和展开区域位置。
- 支持 OpenAI Chat Completions、Responses 和 Anthropic Messages 三种接口格式，以及按供应商配置推理强度。
- 支持全局快捷键唤起类似 Spotlight 的 AI 输入框。
- AI 输入框支持文字、图片和图文混合输入，可选取图片或用 `⌘V` 粘贴截图，发送前可预览和移除。
- 可设置 AI 操作是否需要用户确认。
- 支持 AI 批量操作，关闭确认后会直接执行并返回结果。
- 支持跨会话、跨重启的全局记忆，自动记录稳定偏好，也可通过对话读写；清空始终需要二次确认。
- 支持智能提醒：截止时间临近提醒、可选 AI 后台轮询提醒、系统通知和岛式提醒面板。
- 本地保存调试日志，包含 AI 请求、回复和应用事件。
- 支持开机自启开关。

## 使用方式

barNoticer 主要由三个界面组成：

- 岛面板：用于快速查看、完成事项、展开备注，并可唤出新建事项小面板。
- 新建事项小面板：用于快速创建事项，支持备注、重要性、分组、DDL、多时间点和重复规则。
- 主面板：用于完整管理事项、分组、AI 设置、岛位置设置和应用偏好。

岛面板可以按重要性或自定义分组展示事项。宽体模式会横向展示更多内容；当分组数量超过可显示范围时，宽体分组视图支持横向滚动。

事项可以只设置一个截止时间，也可以设置多个具体时间点。多时间点事项会优先展示最近一次还没到来的时间点；重复事项在完成当前周期后会自动滚动到下一次出现时间，而不是直接结束整个事项。

## AI 助手

barNoticer 支持 OpenAI 兼容的 Chat Completions、Responses，以及 Anthropic Messages 接口。用户可以在设置中配置多个供应商，指定一个使用或按列表顺序尝试：

- API Base URL
- 模型名称
- API Key
- 响应格式
- OpenAI 推理强度：供应商默认（不发送）、`none`、`minimal`、`low`、`medium`、`high`、`xhigh`
- 全局快捷键
- AI 执行操作前是否需要确认

AI 助手只围绕待办管理工作：总结未完成事项、总结已完成事项、分析完成习惯、给出任务建议、创建事项、修改事项、完成事项、删除事项、管理分组、设置时间安排和重复规则，以及生成指定时段的总结并在确认后保存。

应用会把本地结构化上下文提供给 AI，包括未完成事项、已完成事项、分组、截止时间、多时间点、重复规则、创建时间、已保存的新格式总结、当前日期和时区。这样用户使用“今天”“明天”“下周三”等相对日期时，模型可以根据当前上下文理解。

AI 操作支持批量执行。开启“需要确认”时，用户可以整体确认或逐项处理；关闭确认时，AI 会直接执行允许的待办操作，并用一条简洁回复说明结果。总结保存始终需要逐份确认，清空全局记忆始终需要二次确认，不受普通审批开关影响。

`update_todo` 支持标题、备注、重要性、分组、DDL／多时间点／重复计划、提醒、自动完成、完成状态、创建时间、更新时间及重复任务最近完成周期。可以修改已完成事项并将其恢复到进行中；任务 UUID、内部编码和提醒投递标记由系统维护，不作为可编辑业务字段。

`is_completed=true` 标记整项完成，`false` 恢复未完成；重复事项的 `complete_todo` 仍只完成当前一次并推进下一次，结束整个重复事项则使用 `is_completed=true`。`created_at` 和 `updated_at` 可按用户要求修正历史时间（已完成事项以更新时间记录完成时间）；省略更新时间则记录本次修改时间。`last_completed_occurrence_at` 或 `clear_last_completed_occurrence` 用于修正／重置重复进度，自动完成仍开启时调度器会继续推进到期周期。

修改时只提供需要变更的字段；省略或 `null` 保留原值。已有重复计划可单独修改规则、起点或每 N 天间隔，不清空其余设置。使用 `clear_note`、`clear_group`、`clear_schedule`、`clear_reminder` 分别清空备注、移回默认分组、清除日程或关闭提醒；同一字段不能同时设置新值并清空。错误组合在修改模型前拒绝，并沿用工具错误反馈与纠错机制。

工具参数不是有效 JSON、缺少必填字段、字段类型／枚举／日期／UUID 错误时，应用会把具体错误作为对应调用的工具结果发送回模型，让它修正后继续。同一批中已成功或已待确认的操作不会被应用整批重放。每轮处理最多发起 6 次工具请求；仍不能完成时显示失败，保留已执行结果和待确认操作，不把失败报告为成功。

Chat Completions 使用 `reasoning_effort`，Responses 使用 `reasoning.effort`；未选择强度时不发送推理设置。Responses 在明确选择非 `none` 强度时请求自动推理摘要，并在后续工具轮次原样回传同一供应商的输出项（包括加密推理项）；切换供应商时不会转发私有推理项。支持的强度和摘要取决于模型及供应商，不支持时可改回默认。

输入框下方保留约三行、可滚动的透明活动区，增量显示实际返回的思考摘要、工具准备进度和参数纠错信息。它不会随内容增长撑大窗口，也不会编造模型未返回的思考过程。正文随流式分片更新并滚动到最新内容；完成后保持回复区展开，长回复可上下滚动查看。新对话或再次提交时清空活动记录。

聊天请求默认启用 `stream: true`，支持 Chat Completions、Responses 和 Anthropic Messages 的 SSE 事件。接口忽略流式设置而返回普通 JSON 时，会直接展示完整回复，不会因此额外重发请求；后台提醒和连接测试仍使用完整响应。工具参数可以分片到达，但只有收齐并收到有效完成标记后才交给执行器，参数错误仍按原有机制反馈纠正。中断会明确标注回复未完成，保留重试草稿及已经执行／待确认的操作；新对话会取消旧流，避免旧内容继续追加。

聊天和新建事项面板跟随触发时鼠标所在屏幕，在刘海／菜单栏安全区域下方展开；无刘海或较小屏幕会约束在可见范围内。提醒的光晕与内容使用同一屏幕，并继续遵守已配置的位置和大小。弹窗显示期间暂停待办岛的悬停展开；减少动态效果时直接呈现，关闭动画不会误隐藏刚重新打开的窗口。分组编辑、事项设置和危险操作确认继续使用系统原生 popover、sheet 和 alert。

API Key 优先保存在系统 Data Protection Keychain 中，本地 ad-hoc 构建则保存在受限权限（`0600`、排除备份）的独立本机凭据文件中，不再以明文存入 `UserDefaults`，也不会提交到仓库。

图片输入需要所配置的模型和接口支持对应协议的图文消息（Chat Completions 的 `image_url`、Responses 的 `input_image` 或 Anthropic 图片内容）。每次最多添加 4 张图片，单张原文件不超过 20 MB；发送前会将长边缩至最多 2048 像素并转为 JPEG。图片会随当前会话发送至已配置的 AI 服务；尚未执行操作的请求失败时会恢复输入，方便重试。

关闭 AI 面板或点击其他位置只会隐藏窗口，保留当前输入、会话和待确认操作。请求会继续在后台回复并按确认设置执行操作；窗口隐藏时，完成或失败都会通过与提醒相同的弹窗通知，点击“继续对话”或“查看待确认操作”可回到当前会话。重新唤起面板会接着上次对话，窗口已打开时直接显示回复。

点击“新对话”会清空会话及图片，并停止尚未完成的旧请求；已经执行的事项操作不会撤销。`Esc` 在有内容时先执行新对话，在空白会话时才关闭面板；输入法组字和确认弹窗期间不触发清空。会话保留在本次应用运行期间，退出应用后不会恢复。

### 总结记录

在主面板侧栏选择“记录 → 总结”查看已保存的新格式记录。列表按保存时间倒序排列，详情展示标题、覆盖时段、保存时间和完整正文，可选择复制文本。

对 AI 说“生成今天的总结”或“总结 11 月 9 日到 13 日的进展”，助手会先给出标题、时间跨度和正文，并询问是否保存。点击这份预览的“保存总结”才落盘；点击“不保存”会放弃草稿。普通操作免审批、批量执行或模型声称“已保存”都不能代替保存确认；保存失败时保留待确认草稿并显示错误。

每份总结是一个独立的 `<UUID>.json` 文件，包含 `formatVersion`、`id`、`title`、`periodStart`、`periodEnd`、`content` 和 `createdAt`。时间使用 ISO8601，范围为起点包含、终点不含，界面按本机时区显示。安装版默认目录：

```text
~/Library/Containers/com.LEOibyug.barNoticer/Data/Library/Application Support/barNoticer/Summaries/
```

页面右上角的“打开保存位置”可进入该目录备份或管理文件；外部修改后点击“刷新”重新读取。损坏或不支持的文件会显示读取错误，不会删除原文件，其他可读取记录仍保留。

旧版 SwiftData 总结不迁移、不删除，不会出现在新页面或新总结上下文中。原数据库实体仅保留用于既有待办数据库的兼容性，后续不再向它写入总结。

### 全局记忆

长期记忆不会自动附在每轮上下文中。模型需要用户信息、偏好或已有定义时，会主动调用工具查阅，之后才把内容发送给 AI 服务。查阅结果只参与当前这轮处理，不写入后续对话历史；同一轮重复查阅时，旧结果会被替换。输入框会显示“查阅记忆中…”“记录记忆中…”或“查阅事项中…”等状态。AI 可以自动记录用户本人提到的稳定信息和偏好；也可以明确要求“记住我喜欢简短回答”“把我的称呼改成小林”或“你记住了哪些信息”。同一主题按名称更新，明确保存的定义不会被自动推断覆盖。

偏好优先级为：当前用户要求 > 明确保存的用户定义 > 自动记录的信息 > 内置默认偏好。工具格式、数据完整性、提醒的只读边界和清空确认规则仍然有效。后台提醒也可以按需查阅记忆，只有读取权限；更新或清空后，旧的预生成文案会失效。

在“AI 设置 → 全局记忆”可查看记录并点击“清空全部记忆”，也可以在聊天中要求 AI 清空。两种入口都必须在弹窗中再次确认；关闭普通操作审批或点击“全部执行”也不能跳过。取消不会删除，确认时若记忆已发生变化，需要重新发起清空。清空发生在聊天请求途中时，该轮请求会停止，以防旧回复重新写入。

记忆仅持久化在本机应用配置中，被查阅时才发送给配置的 AI 服务。新对话不删除记忆，清空记忆不删除待办和聊天记录。最多保存 64 条、合计 16000 字，单条内容不超过 1000 字。

## 智能提醒

barNoticer 的提醒系统包含两类触发方式：

- 截止时间或安排时间临近时触发。默认在提前 1 天和 12 小时进入检查窗口。
- 可选的 AI 后台轮询提醒。该功能默认关闭，避免安装后自动产生 API 成本。

在单次 DDL 任务的新建面板或事项设置中，可以启用“DDL 提前提醒”，输入分钟、小时或天；填 0 表示到点提醒。也可以对 AI 说“明天三点交作业，提前 30 分钟提醒我”。这类提醒由本地定时器独立触发，关闭“后台 AI 提醒判断”不会影响它；每个任务的同一次提醒只发送一次，修改 DDL 会重新安排时间。完成、删除任务或关闭该任务的提醒后不再触发。目前自定义提前提醒仅适用于单次 DDL。

“使用 AI 编写定时提醒文案”是独立开关。开启后会提前调用 AI 润色，到点时如果 AI 不可用或尚未完成，则立即使用本地文案，AI 不能否决用户主动设置的提醒。应用需保持运行；休眠或退出期间错过的提醒会在唤醒或再次启动后补发一次。

后台 AI 主动提醒开启时，应用会结合当前时间、时区、全部事项、分组、时间安排、重复规则和近期提醒历史判断是否提醒；关闭后停止轮询和默认的提前 1 天、12 小时判断。AI 不会在后台提醒流程中修改任务数据。

提醒呈现支持两种渠道：

- 系统通知：默认开启，可在提醒设置中关闭。
- 岛式提醒：热区附近先出现光晕闪烁，然后从刘海区域展开提醒面板。面板会把相关事项统一渲染在文案下方，并支持完成或稍后提醒。

如果 AI API 不可用，截止时间提醒会使用本地兜底文案，避免错过重要事项。

```text

```

仓库包含从源码构建所需的 Xcode 工程和测试文件。`xcuserdata`、DerivedData、构建产物、运行日志和本机配置不会提交。

## 从源码构建

克隆仓库后可以直接用 Xcode 打开：

```bash
git clone git@github.com:LEOibyug/barNoticer.git
cd barNoticer
open barNoticer.xcodeproj
```

在 Xcode 中选择 `barNoticer` scheme，然后运行即可。

也可以使用命令行构建 Release 版本：

```bash
xcodebuild build \
  -project barNoticer.xcodeproj \
  -scheme barNoticer \
  -configuration Release \
  -destination 'platform=macOS' \
  -derivedDataPath build/Release
```

安装到本机：

```bash
ditto build/Release/Build/Products/Release/barNoticer.app /Applications/barNoticer.app
open /Applications/barNoticer.app
```

本地构建默认使用 Xcode 的本地签名。若要公开分发，需要自行配置 Developer ID 签名、Hardened Runtime 和 notarization。

## 运行测试

```bash
xcodebuild test \
  -project barNoticer.xcodeproj \
  -scheme barNoticer \
  -destination 'platform=macOS' \
  -parallel-testing-enabled NO \
  -derivedDataPath build/Tests
```

测试包含真实 AppKit 窗口与焦点切换，使用串行执行，避免多个测试进程争用桌面焦点。

## 日志

应用会维护轻量级本地日志，便于调试 AI 请求、回复和窗口行为。日志位置可在应用设置中查看，通常位于应用容器内：

```text
~/Library/Containers/com.LEOibyug.barNoticer/Data/Library/Application Support/barNoticer/Logs/barNoticer.log
```

运行日志、用户配置、API Key 和本机数据都不会作为仓库内容提交。

## 数据模型

barNoticer 使用 SwiftData 保存待办数据，注册模型包括：

- `TodoItem`
- `TodoGroup`
- `DailySummary`（仅保留旧数据库实体，后续总结不再使用）

事项时间安排由 `TodoSchedule` 相关逻辑处理，支持单次截止时间、多时间点和每天/每周/每月重复规则。

新总结使用 `SavedSummary` 和 `SummaryStore`，以独立 JSON 文件保存，不依赖 SwiftData 总结表。

内置默认分组名为 `默认分组`，不能删除。删除自定义分组时，该分组下的事项会回到默认分组。
